# Phase 03.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| System picker to app cache | User-selected photos, image files, and explicit folder children enter the app through platform-native picker APIs only. | Selected image bytes, opaque staged `file://` refs, source metadata |
| Native platform channel to Dart | Native picker/OCR adapters return staged refs and normalized OCR data to Dart. | Source picker result maps, retry handles, OCR blocks |
| App cache to app-internal durable storage | Confirmed saves copy staged original bytes into app support storage. | Original image bytes, generated internal copy path |
| Application layer to SQLite | Confirmed passes, scan fingerprints, and copy registry rows persist locally. | Pass metadata, OCR text, confidence, source fingerprints, copy registry |
| Test injection to production composition | Tests may inject fakes, but the default app path must use real local adapters. | Controller/dependency constructors |

## Threat Register

| Threat ID | Category | Component | Disposition | Mitigation | Status |
|-----------|----------|-----------|-------------|------------|--------|
| T-03.1-01 | Tampering / Data Integrity | SQLite pass repository | mitigate | `CouponKeeperDatabase` stores explicit columns for every pass/source/confidence field; `SqlitePassRepository` round-trip tests close and reopen the database and assert metadata, OCR, confidence, timestamps, and image copy path survive. | closed |
| T-03.1-02 | Information Disclosure / Integrity | Local image copies | mitigate | `LocalImageCopyStore` uses generated `<id>.image` names under `coupon-images`, copies original bytes with `File.copy`, and tests assert byte equality plus filename privacy. | closed |
| T-03.1-03 | Tampering / Availability | Candidate save atomicity | mitigate | `ImageCopyResult.created` lets `CandidateDiscoveryController` delete only newly created copies when repository save fails; reused copies are preserved and review state does not advance on copy/repository failure. | closed |
| T-03.1-04 | Elevation of Privilege / Information Disclosure | Source picker scope | mitigate | UI exposes explicit photos, downloads/files, and folder source types; Android uses system picker/SAF; folder enumeration is direct-child only; tests assert no recursive traversal marker and no broad scan copy. | closed |
| T-03.1-05 | Elevation of Privilege / Information Disclosure | Android storage access | mitigate | Android implementation uses `PickMultipleVisualMedia`, `ACTION_OPEN_DOCUMENT`, and `ACTION_OPEN_DOCUMENT_TREE`; manifest contract tests reject `READ_MEDIA_IMAGES`, `READ_EXTERNAL_STORAGE`, and `MANAGE_EXTERNAL_STORAGE`. | closed |
| T-03.1-06 | Information Disclosure / Availability | iOS security-scoped files | mitigate | iOS picker uses `PHPickerViewController` and `UIDocumentPickerViewController`; external file reads balance `startAccessingSecurityScopedResource()` and `stopAccessingSecurityScopedResource()` with `defer`, coordinate reads with `NSFileCoordinator`, and stage bytes into app cache under opaque filenames. | closed |
| T-03.1-07 | Tampering / Availability | Failed-item retry | mitigate | `GuidedScanController` retains failed items/source handles separately, exposes `retryFailed()`, and tests prove retry processes only failed items without reopening `pick()`. | closed |
| T-03.1-08 | Denial of Service / UX Recovery | Repeated failure recovery | mitigate | Partial and failed states keep retry, choose-again, and retained-candidate report actions visible; tests prove successful candidates remain after sibling failure and repeated retry failure. | closed |
| T-03.1-09 | Spoofing / Integrity | Production composition | mitigate | `CouponKeeperDependencies.production()` owns `SqlitePassRepository`, `SqliteScanFingerprintCache`, `LocalImageCopyStore`, `MethodChannelScanSourcePicker`, and `MethodChannelOcrTextRecognizer`; production composition tests reject demo/fake/in-memory imports from the default path. | closed |

*Status: open · closed*
*Disposition: mitigate (implementation required) · accept (documented risk) · transfer (third-party)*
