<objective>
Define the pass-centric domain model and local storage contracts that future scan, wallet, cleanup, reminder, and SQLite work will depend on.
</objective>

<user_story>
As a Coupon Keeper user, I want saved passes to keep their identity, expiry, source state, image copy path, OCR text, and confidence, so that the app can safely show and filter them even when the original file disappears.
</user_story>

<must_haves>
- PASS-01: Store a pass with type, title, brand, estimated value, expiry, status, source metadata, image copy path, OCR text, and confidence.
- PASS-02: Model app-internal image copy path separately from source availability.
- PASS-03: Represent active, used, expired, cleanup-candidate, and needs-review states.
- D-05: `PassType` values are `coupon`, `exchange`, `membership`, `barcode`, `other`.
- D-06: `PassStatus` values are `active`, `used`, `expired`, `cleanupCandidate`, `needsReview`.
- D-07: Effective expiry uses stored status plus expiry-date calculation.
- D-08: Confidence is field-level, including `expiry`, `value`, `brand`, `barcode`, `overall`.
- D-09: Repository contract includes CRUD and status/effective-status queries.
- D-11: In-memory repository remains the official test double. Repository contract includes CRUD and status/effective-status queries with an in-memory official test double.
- D-10: Image copy store contract is defined with fake/in-memory implementation.
- D-12: Source metadata includes source ref, fingerprint, availability, and missing reason. Image copy store contract and source metadata include source ref, fingerprint, availability, and missing reason.
</must_haves>

<truths>
- D-05: Pass type supports coupon, exchange, membership, barcode, and other.
- D-06: Pass status supports active, used, expired, cleanupCandidate, and needsReview.
- D-07: Effective expiry uses stored status plus expiry-date calculation.
- D-08: Confidence is stored as field-level confidence, including expiry, value, brand, barcode, and overall.
- D-09: PassRepository contract includes CRUD, id lookup, status queries, and expiry-corrected queries.
- D-10: Image copy store is a contract with fake or in-memory implementation in Phase 1.
- D-11: In-memory repository is the official test double.
- D-12: Source metadata includes original ref, platform source type, fingerprint, importedAt, availability, and missing reason.
</truths>

<context_decision_coverage>
- D-05: `Pass.type`은 `coupon`, `exchange`, `membership`, `barcode`, `other`를 지원한다. MVP 화면은 쿠폰/교환권에 집중하되 내부 모델은 local pass finder 확장성을 갖춘다.
- D-06: `Pass.status`는 `active`, `used`, `expired`, `cleanupCandidate`, `needsReview`를 지원한다. OCR 후보 확인과 정리 후보 흐름까지 같은 수명주기 안에서 다룬다.
- D-07: 만료 상태는 저장된 status와 expiry 기반 계산 보정을 함께 사용한다. DB에 status를 저장하되, `active` pass라도 expiry가 지난 경우 도메인/조회 레이어에서 expired처럼 다룬다.
- D-08: OCR confidence는 단일 숫자가 아니라 필드별 confidence map으로 저장할 수 있게 한다. 최소 키는 `expiry`, `value`, `brand`, `barcode`, `overall`을 고려한다.
- D-09: `PassRepository` 계약은 CRUD, id 조회, 상태별 조회, 만료 보정 조회를 포함한다. Phase 1부터 Today/Wallet/Reminder가 의존할 조회 의미를 고정한다.
- D-10: 앱 내부 이미지 사본 저장소는 Phase 1에서 계약만 정의하고 fake/in-memory 구현을 제공한다. 실제 파일 복사와 플랫폼 경로 처리는 Phase 2 이후에 연결한다.
- D-11: In-memory repository를 공식 test double로 유지한다. SQLite 구현 전에도 domain/application/widget 테스트가 동일한 repository contract behavior를 검증할 수 있어야 한다.
- D-12: `source metadata`는 원본 URI/path, platform source type, fingerprint/hash, importedAt, availability, missing reason을 담을 수 있게 모델링한다.
</context_decision_coverage>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| Domain model stores real local user paths in tests | medium | Use deterministic fake source refs and image copy paths in fixtures only. |
| Expired state becomes stale or overwrites explicit user states | medium | Implement effective status as a pure calculation that only reclassifies stored `active` passes. |
| Future SQLite implementation diverges from in-memory behavior | medium | Treat in-memory repository tests as contract tests and name them accordingly. |
</threat_model>
