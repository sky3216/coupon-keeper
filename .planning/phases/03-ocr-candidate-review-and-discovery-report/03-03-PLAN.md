<objective>
Implement the real on-device OCR platform channel while keeping all app logic fake-testable and normalized.
</objective>

<user_story>
사용자로서 나는 선택한 쿠폰 이미지의 텍스트가 서버 전송 없이 내 기기에서 인식되기를 원한다.
</user_story>

<must_haves>
- Use Flutter `MethodChannel` with a unique app-prefixed name.
- Return JSON-like normalized block maps only.
- Android models are bundled so first scan does not depend on dynamic model download.
- iOS channel registration uses the existing implicit-engine lifecycle.
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-03-07: OCR model requires network download during first scan | high | Use bundled ML Kit Latin and Korean dependencies. |
| T-03-08: Platform result schema differs between iOS and Android | high | Both native handlers return the same normalized map schema and Dart decode tests cover it. |
| T-03-09: iOS channel crashes under UIScene lifecycle | high | Register in existing `didInitializeImplicitFlutterEngine`, not a nil-window path. |
</threat_model>

  <action>
  Add `MethodChannelOcrTextRecognizer` using one app-prefixed channel such as `coupon_keeper/ocr` and method `recognizeText`. Send `ScanItem.platformSourceRef`, never fingerprint `sourceToken`, and decode a map containing `fullText`, `blocks`, block `text`, nullable `confidence`, normalized `bounds`, and nested `lines`.   - Tests use `setMockMethodCallHandler` and do not need a device.
  </acceptance_criteria>

  - Native response map contains normalized blocks and lines accepted by the Dart decode test.

  - `flutter build apk --debug` succeeds.
