<objective>
Connect Phase 2 selected-item processing to a fake-driven Phase 3 discovery session and implement explicit save, reject, and manual registration orchestration.
</objective>

<user_story>
사용자로서 나는 OCR 후보를 한 장씩 확인하고, 맞으면 저장하고, 아니면 넘기며, OCR이 실패해도 선택한 이미지로 직접 등록하기를 원한다.
</user_story>

<must_haves>
- `GuidedScanController` selected-items-only, cancel, failure, and duplicate semantics remain green.
- Fingerprint cache is updated only after OCR/candidate processing succeeds.
- Repository writes happen only from explicit save/manual actions.
- Image copy occurs only for a confirmed or manual pass.
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-03-04: OCR candidates are silently auto-saved | high | Separate session candidates from repository writes and test repository remains empty until explicit action. |
| T-03-05: Failed OCR item is marked seen and cannot be retried | high | Inject session processing into existing `ScanItemProcessor`; throw on OCR failure so Phase 2 controller does not call `markSeen`. |
| T-03-06: Manual save loses selected image durability | medium | Always call `ImageCopyStore.copyIntoAppStorage()` before creating confirmed/manual `Pass`. |
</threat_model>
