<objective>
Connect the real local adapters as the default app path and make partial failure recovery honest: preserve useful work, retry failed items only, and keep choose-again reachable.
</objective>

<user_story>
사용자로서 나는 여러 쿠폰 중 일부를 읽지 못하더라도 성공한 후보를 잃지 않고, 실패한 항목만 차분하게 다시 시도하고 싶다.
</user_story>

<must_haves>
- `GuidedScanController.retryFailed()` never launches a fresh system picker.
- Partial success can continue to retained candidate review.
- Production app composition uses SQLite, local image copies, real selected-source picker, and MethodChannel OCR.
- Fake adapters remain injectable in tests.
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-03.1-07: Retry reprocesses successes, reopens picker, or loses successful candidates | high | Persist failed item lists separately, expose `retryFailed()`, and test processor call order. |
| T-03.1-08: Repeated failure traps the user or hides retained successful candidates | medium | Render retry, choose-again, and continue-with-success actions from explicit controller state. |
| T-03.1-09: Default app still launches demo picker, fake OCR, or memory storage | high | Move production composition to one dependency owner and add static/widget regression coverage. |
</threat_model>
