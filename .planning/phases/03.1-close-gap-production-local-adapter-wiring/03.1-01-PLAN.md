<objective>
Add the durable local storage layer that Phase 4 can rely on: versioned SQLite rows, persisted scan fingerprints, and reusable app-internal original-byte image copies.
</objective>

<user_story>
사용자로서 나는 원본 사진을 옮기거나 앱을 다시 열어도 확인해서 저장한 쿠폰과 이미지가 기기 안에 안전하게 남아 있기를 원한다.
</user_story>

<must_haves>
- `SqlitePassRepository` implements every method in `PassRepository`.
- `SqliteScanFingerprintCache` preserves duplicate skip semantics across database reopen.
- `LocalImageCopyStore` stores bytes below application support `coupon-images/`.
- Candidate save rolls back only newly-created copies when SQLite save fails.
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-03.1-01: SQLite round-trip drops status, source metadata, OCR text, or confidence | high | Use explicit columns for every `Pass` field and contract tests that close and reopen the database. |
| T-03.1-02: Internal filenames leak original names or recompression damages barcode fidelity | high | Copy bytes with `File.copy`, generate opaque IDs, and assert byte equality plus filename privacy. |
| T-03.1-03: Copy succeeds but repository save fails, leaving an orphan or deleting a reused copy | high | Return `ImageCopyResult(path, created)` and delete only a newly-created copy on downstream save failure. |
</threat_model>
