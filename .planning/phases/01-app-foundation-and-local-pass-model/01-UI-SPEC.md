# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-phase, verified against Phase 1 context and research.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Flutter Material 3 |
| Preset | Not applicable |
| Component library | Flutter `material` widgets |
| Icon library | Flutter Material Icons |
| Font | System default; Korean text must render legibly at 16px+ |

Phase 1 must create a compact mobile-first mini design system, not a marketing-style landing page. The product should feel like a quiet wallet utility for repeated store-front use: dense enough to scan, calm enough to trust, and direct enough to start a guided scan quickly.

---

## Phase 1 Screen Contract

### App Shell

- Use three bottom destinations only: `Today`, `Wallet`, `Scan`.
- First selected destination is `Today`.
- Use Material 3 `NavigationBar` and `NavigationDestination` or an equivalent Flutter bottom navigation component.
- Destination labels are always visible.
- Each destination must have a screen reader label matching the visible label.
- The app shell must be launchable without server, login, cloud sync, native permission prompts, or sample personal coupon data.

### Today

Purpose: first-use action and later expiry overview.

Phase 1 state:

- Empty/first-run screen is scan CTA centered.
- Copy tone is loss-prevention, not photo cleanup.
- Primary CTA navigates to the `Scan` tab only. It must not open photo picker, file picker, OCR, or scan progress in Phase 1.
- No fake dashboard metrics. Do not show made-up protected value, fake coupon count, or sample pass cards.

Required copy:

- Heading: `잊고 있던 쿠폰을 찾아볼까요?`
- Body: `사진과 다운로드에 흩어진 쿠폰을 선택한 범위 안에서 찾아 지갑에 모아둘 수 있어요.`
- Primary CTA: `숨어 있는 쿠폰 찾기`
- Secondary trust line: `선택한 항목만 기기 안에서 확인합니다.`

### Wallet

Purpose: quiet result space for saved passes.

Phase 1 state:

- Empty state explains that saved passes will appear here after scan and confirmation.
- Wallet must not use decorative sample pass cards or fake coupon images.
- Wallet may show disabled/filter placeholder chips only when clearly empty and non-interactive; otherwise defer filters until pass data exists.
- Scan CTA can navigate to `Scan`, but it is visually secondary to Today's primary CTA.

Required copy:

- Heading: `아직 지갑이 비어 있어요`
- Body: `스캔 후 저장한 쿠폰과 바코드 패스가 이곳에 모입니다.`
- CTA: `Scan으로 이동`

### Scan

Purpose: action space prepared for guided scan.

Phase 1 state:

- Show the start surface for guided scan without invoking platform pickers.
- Present the next Phase 2 actions as disabled or "coming next" affordances only if needed for layout; avoid fake functionality.
- Make it clear that scan begins from user-selected photos/downloads.

Required copy:

- Heading: `선택한 항목에서 쿠폰을 찾습니다`
- Body: `사진이나 다운로드 파일을 직접 고르면, 다음 단계에서 쿠폰 후보를 찾아 보여줍니다.`
- Primary CTA label for Phase 1 shell: `스캔 준비`
- If the CTA is disabled, semantic label must explain `사진 선택 기능은 다음 단계에서 연결됩니다`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip inner gaps |
| sm | 8px | Compact row gaps, chip vertical padding |
| md | 16px | Default screen padding, button text padding |
| lg | 24px | Section spacing, empty-state block gap |
| xl | 32px | Top content offset, large CTA separation |
| 2xl | 48px | Empty-state vertical grouping |
| 3xl | 64px | Rare page-level spacing on tall screens only |

Exceptions: none.

Layout constraints:

- Screen horizontal padding: 16px on 320px-wide screens, 20px on wider phones.
- Primary CTA height: minimum 48px.
- Bottom navigation item tap target: minimum 44px high.
- Empty-state content should stay above the bottom navigation and not be hidden by safe-area insets.
- Avoid nested cards. Page sections are unframed; cards are allowed only for repeated pass rows or future modal content.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.45 |
| Label | 13px | 600 | 1.30 |
| Meta | 14px | 400 | 1.35 |
| Section | 18px | 700 | 1.30 |
| Heading | 24px | 700 | 1.25 |
| Display | Not used in Phase 1 | Not applicable | Not applicable |

Typography rules:

- Do not scale font size with viewport width.
- Letter spacing is 0.
- Body text must not be smaller than 16px.
- Button labels must fit at 320px width without truncation.
- Brand/title text in future pass rows may wrap to 2 lines and then ellipsize.
- Avoid hero-scale type inside tabs; this is an operational utility, not a landing page.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F6F2` | App background |
| Secondary (30%) | `#FFFFFF` | Surfaces, bottom nav, pass rows |
| Text primary | `#171717` | Primary text |
| Text secondary | `#5F625D` | Body/supporting text |
| Border | `#DAD8D0` | Dividers, chip borders |
| Accent (10%) | `#1F7A5A` | Primary CTA, active nav indicator, positive scan action |
| Accent soft | `#E5F3ED` | Active/positive chip background |
| Warning | `#9A6500` | D-7 / expiring soon text and icon |
| Warning soft | `#FFF3D7` | Expiring chip background |
| Danger | `#B3261E` | Expired/destructive status only |
| Danger soft | `#FCE8E6` | Expired chip background |
| Neutral chip | `#EEEDE7` | Used/source-missing/needs-review chip background |

Accent reserved for:

- Today primary CTA
- Scan primary action surface
- Active bottom navigation destination
- Active or healthy state chips

Color rules:

- Do not use purple/purple-blue gradients, decorative orbs, bokeh blobs, or one-note monochrome palettes.
- Do not express status by color alone. Every status chip must include text; icons are allowed but not required.
- Text/background contrast must target 4.5:1 or better for normal text.
- Destructive red is reserved for expired/destructive states only.

## Component Contracts

### Primary Button

- Height: at least 48px.
- Border radius: 8px.
- One primary button per screen.
- Label uses specific verb + noun.
- Today primary button text is `숨어 있는 쿠폰 찾기`.
- Semantics label for Today CTA: `숨어 있는 쿠폰 찾기, Scan 탭으로 이동`.

### Secondary Text Button

- Used for low-emphasis navigation such as Wallet empty state to Scan.
- Minimum tap target: 44px high.
- Must not compete visually with Today primary CTA.

### Status Chip

Required chips:

| State | Text | Color Role | Semantic Label |
|-------|------|------------|----------------|
| D-7 | `D-7` | Warning | `만료 7일 전` |
| Today expiry | `오늘 만료` | Danger | `오늘 만료` |
| Expired | `만료됨` | Danger | `만료됨` |
| Used | `사용 완료` | Neutral | `사용 완료` |
| Needs review | `확인 필요` | Warning/Neutral | `확인 필요` |
| Source missing | `원본 없음` | Neutral | `원본 파일을 찾을 수 없음` |

Chip rules:

- Height: 28px minimum.
- Horizontal padding: 8px minimum.
- Border radius: 8px or less.
- Text must remain visible at 320px width.

### Pass Row

Phase 1 may implement a reusable row surface even without real passes.

- Height: stable minimum 72px.
- Contains thumbnail slot, brand/title block, expiry text, one status chip.
- No large decorative card grid.
- Thumbnail is small and secondary; list scanability wins over preview size.

### Empty State

- Empty states must contain heading, body, and a next action.
- No placeholder strings: `TODO`, `Lorem ipsum`, `Coming soon` are not allowed in user-facing copy.
- Empty-state body should be 1-2 short Korean sentences.
- Empty-state visual can use a simple Material icon, but the icon must be decorative or have a semantic label.

### Bottom Navigation

- Exactly three items: `Today`, `Wallet`, `Scan`.
- Labels always visible.
- Do not add badges in Phase 1.
- Do not add a fourth "Settings" or "Pro" tab.

## Interaction Contracts

### Today CTA

- Tapping `숨어 있는 쿠폰 찾기` changes selected bottom tab to `Scan`.
- It does not request permission.
- It does not open a picker.
- It does not create pass data.

### Wallet CTA

- Tapping `Scan으로 이동` changes selected bottom tab to `Scan`.
- It is secondary emphasis.

### Scan CTA

- If enabled in Phase 1, it opens no native picker and should show only a non-blocking shell state.
- If disabled in Phase 1, it must expose a clear semantic disabled reason for tests and assistive technology.

### Small Screen

- At 320x568 logical size, all primary actions remain visible without horizontal scrolling.
- No on-screen text overlaps bottom navigation.
- Buttons and chips keep stable dimensions when text changes.

---

## Accessibility Contract

- Minimum touch target: 44px; primary buttons should be 48px high.
- Body text: 16px or larger.
- Normal text contrast: 4.5:1 target or better.
- Status is never color-only.
- Semantics labels required for:
  - Today primary CTA
  - Wallet CTA
  - Scan CTA
  - Bottom navigation destinations
  - Status chips
  - Future pass row combined label
- Future pass row semantic label format:
  - `{brand} {title}, {expiry/status}, {source state}`
  - Example: `스타벅스 아메리카노 쿠폰, 오늘 만료, 원본 있음`
