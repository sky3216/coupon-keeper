# Phase 2 — UI Design Contract

> Visual and interaction contract for Guided Scan Intake. Generated by gsd-ui-phase, verified against Phase 2 context and Phase 1 design system.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Flutter Material 3 |
| Preset | Not applicable |
| Component library | Flutter `material` widgets plus local reusable widgets |
| Icon library | Flutter Material Icons |
| Font | System default; Korean text must render legibly at 16px+ |

Phase 2 extends the Phase 1 compact mobile utility system. The Scan tab becomes a guided action surface, not a decorative onboarding page and not a fake discovery report. The UI must feel controlled, local, and finite: the user explicitly chooses sources, sees what is being processed, and can cancel.

---

## Phase 2 Screen Contract

### App Shell Continuity

- Keep the same three bottom destinations only: `Today`, `Wallet`, `Scan`.
- Today and Wallet CTAs navigate to the `Scan` tab first. They must not launch a native picker directly from another tab.
- Scan owns the intake flow state: start, selecting, progress, cancelled, empty result, partial result, and access/error states.
- Do not add a new top-level route, modal-heavy onboarding flow, Pro tab, settings tab, or broad auto-scan entry.

### Scan Start

Purpose: let the user choose exactly where to scan.

Required structure:

- Heading: `어디에서 쿠폰을 찾을까요?`
- Body: `선택한 사진과 파일만 기기 안에서 확인합니다.`
- Source choice 1: `사진에서 찾기`
- Source choice 1 support: `사진 앱에서 직접 고른 항목만 확인해요.`
- Source choice 2: `다운로드/파일에서 찾기`
- Source choice 2 support: `다운로드한 이미지나 폴더를 직접 고릅니다.`
- Trust line: `전체 사진첩이나 폴더를 조용히 훑지 않아요.`

Interaction rules:

- Source choices are vertically stacked action rows or compact tiles, not large decorative cards.
- Both source choices have equal visual weight. Do not make downloads look secondary; many target coupons live outside photos.
- Tapping a source choice calls the Phase 2 selection adapter/test double. If the platform adapter is fake, show the same UI states that the real picker will drive.
- If no source is available on the current platform/test environment, keep the control visible but disabled with a semantic disabled reason.

### Scan Progress

Purpose: reassure the user that selected items are being processed in a finite, cancellable batch.

Required copy and data:

- Heading: `선택한 항목을 확인하고 있어요`
- Progress count format: `{processed}/{total} 처리 중`
- Candidate placeholder label: `후보 확인 준비 중`
- Duplicate skip summary when nonzero: `이미 확인한 항목 {count}개는 건너뛰었어요`
- Cancel action: `취소`
- Optional low-emphasis support: `선택한 항목만 기기 안에서 확인합니다.`

Progress display rules:

- Show a determinate progress indicator when `total > 0`.
- Show processed count and total count as text even when a progress bar is present.
- Candidate placeholder must not claim real found coupons. Do not show fake brands, values, expiry dates, saved pass cards, protected value, or discovery report numbers in Phase 2.
- Cancel remains visible and reachable throughout progress.
- Duplicate skip copy appears as a small status row below progress, not as a blocking dialog.

### Cancelled State

Purpose: make cancellation feel reversible, not like an error.

Required copy:

- Heading: `스캔을 멈췄어요`
- Body: `남은 항목은 확인하지 않았습니다. 다시 선택해서 이어갈 수 있어요.`
- Primary action: `다시 선택`
- Secondary action: `Scan 처음으로`

Rules:

- Do not show destructive red for user cancellation.
- If some items were already processed before cancellation, show a neutral summary row: `{processed}개 항목은 확인했어요`.
- The state must not imply saved coupons were created.

### Empty Result

Purpose: no candidates is a valid outcome, not a failure.

Required copy:

- Heading: `이번 선택에서는 쿠폰을 찾지 못했어요`
- Body: `다른 사진이나 다운로드 파일을 선택해 다시 확인할 수 있어요.`
- Primary action: `다시 선택`
- Secondary shell action if included: `수동 등록은 다음 단계에서`

Rules:

- Empty result uses neutral styling and an action path back to source selection.
- Do not use danger/error color.
- Do not show fake suggestions like sample coupons.
- Manual registration may appear only as a disabled or low-emphasis shell affordance. Real manual registration belongs to a later phase.

### Partial Result

Purpose: acknowledge mixed outcomes without making the whole scan feel broken.

Required copy/data:

- Heading: `일부 항목만 확인했어요`
- Summary rows:
  - `확인한 항목 {processed}개`
  - `건너뛴 항목 {skipped}개`
  - `확인하지 못한 항목 {failed}개`
- Primary action: `남은 항목 다시 시도`
- Secondary action: `다시 선택`

Rules:

- Use neutral/warning color roles, not destructive red, unless a user action would delete data.
- Failed item details can be collapsed or summarized. Do not create a long technical error list on the main screen.
- The UI must still make it clear that no data left the device.

### Access or File Error

Purpose: distinguish recoverable access problems from scan failure.

Required state variants:

| Variant | Heading | Body | Primary Action |
|---------|---------|------|----------------|
| Permission/access denied | `선택한 항목을 열 수 없어요` | `권한이 바뀌었거나 선택이 취소되었습니다. 다시 선택해 주세요.` | `다시 선택` |
| File unavailable | `파일을 찾을 수 없어요` | `파일이 이동되었거나 삭제되었을 수 있어요. 다른 항목을 선택해 주세요.` | `다시 선택` |
| Processing failed | `일부 항목을 확인하지 못했어요` | `다시 시도하거나 다른 항목을 선택할 수 있어요.` | `다시 시도` |

Rules:

- Error copy names the problem and the recovery path.
- Avoid OS jargon in primary copy. Technical details, if any, belong behind logs/tests, not visible UI.
- Destructive color is not used because Phase 2 does not delete user data.

### Completion Shell

Purpose: bridge Phase 2 to Phase 3 without pretending OCR/candidate review is finished.

Required copy:

- Heading: `선택한 항목 확인을 마쳤어요`
- Body: `다음 단계에서 쿠폰 후보를 확인할 수 있게 준비합니다.`
- Summary rows:
  - `확인한 항목 {processed}개`
  - `건너뛴 항목 {skipped}개` when nonzero
  - `확인하지 못한 항목 {failed}개` when nonzero
- Primary action label if enabled in Phase 2 shell: `후보 확인 준비`

Rules:

- The completion shell is not the first scan discovery report. Do not show found count, expiring-soon count, expired count, or estimated protected value in Phase 2.
- If `후보 확인 준비` is disabled, semantic label must explain `후보 확인 화면은 다음 단계에서 연결됩니다`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline status row gaps |
| sm | 8px | Choice row inner gaps, progress meta gaps |
| md | 16px | Default screen padding, row padding |
| lg | 24px | Section spacing, heading-to-content gap |
| xl | 32px | Start-state action group separation |
| 2xl | 48px | Empty/result vertical grouping on tall screens |
| 3xl | 64px | Rare page-level spacing on tall screens only |

Exceptions: none.

Layout constraints:

- Screen horizontal padding: 16px on 320px-wide screens, 20px on wider phones.
- Source choice action row minimum height: 72px.
- Primary action minimum height: 48px.
- Secondary/cancel action tap target: minimum 44px.
- Progress bar width uses available content width and never forces horizontal scrolling.
- On 320x568 logical size, the source choices, progress count, and cancel action must remain reachable without text overlap.
- Do not put UI cards inside other cards. Page sections remain unframed; use bordered action rows or flat surfaces for choices.

| Body | 16px | 400 | 1.45 |
| Label | 13px | 600 | 1.30 |
| Meta | 14px | 400 | 1.35 |
| Section | 18px | 700 | 1.30 |
| Heading | 24px | 700 | 1.25 |
| Display | Not used in Phase 2 | Not applicable | Not applicable |

Typography rules:

- Do not scale font size with viewport width.
- Letter spacing is 0.
- Body text must not be smaller than 16px.
- Source choice labels may wrap to 2 lines at 320px but must not truncate.
- Progress count and cancel action must stay readable while processing state changes.
- Avoid hero-scale type; this is a repeated-use mobile tool surface.

- Destructive red is reserved for actual destructive actions; Phase 2 has none.

## Component Contracts

### Source Choice Row

- Height: at least 72px.
- Border radius: 8px.
- Border: 1px `#DAD8D0`.
- Layout: leading Material icon, label, support text, optional trailing chevron.
- Labels:
  - `사진에서 찾기`
  - `다운로드/파일에서 찾기`
- Semantic labels:
  - `사진에서 쿠폰 찾기, 선택한 사진만 확인`
  - `다운로드와 파일에서 쿠폰 찾기, 선택한 파일만 확인`
- Disabled semantic label must include why the source is unavailable.

### Primary Button

- Height: at least 48px.
- Border radius: 8px.
- One primary button per state.
- Labels use specific verb + noun: `다시 선택`, `다시 시도`, `후보 확인 준비`.
- Disabled buttons must expose a semantic disabled reason.

### Cancel Action

- Label: `취소`.
- Placement: visible on progress screen without scrolling on common phone sizes.
- Style: text button or low-emphasis outlined action, not destructive red.
- Semantic label: `스캔 취소, 남은 항목 확인 중지`.

### Progress Summary

- Includes determinate progress bar plus text count.
- Required text format: `{processed}/{total} 처리 중`.
- Candidate placeholder: `후보 확인 준비 중`.
- Duplicate skip summary: `이미 확인한 항목 {count}개는 건너뛰었어요`.
- Summary rows use stable heights so counts changing from one to two digits does not shift surrounding controls noticeably.

### Result Summary Rows

- Minimum row height: 44px.
- Use icon + text or text-only rows; no decorative nested cards.
- Required labels:
  - `확인한 항목 {processed}개`
  - `건너뛴 항목 {skipped}개`
  - `확인하지 못한 항목 {failed}개`
- Rows must be readable at 320px width without horizontal scrolling.

### Empty and Error State

- Reuse `EmptyState` pattern where possible, but keep action labels and headings from this spec.
- Empty/error body should be 1-2 short Korean sentences.
- No placeholder strings: `TODO`, `Lorem ipsum`, `Coming soon` are not allowed in user-facing copy.
- Error states must include a recovery action.

## Interaction Contracts

### Today and Wallet Entry

- Tapping `숨어 있는 쿠폰 찾기` on Today selects the `Scan` tab.
- Tapping `Scan으로 이동` on Wallet selects the `Scan` tab.
- Neither action opens a native picker directly.
- Scan start state should be visible after navigation.

### Source Selection

- Tapping `사진에서 찾기` starts the photo-selection adapter/test double.
- Tapping `다운로드/파일에서 찾기` starts the file/folder-selection adapter/test double.
- If selection returns zero items, show the empty result or a cancelled/neutral state, not a progress screen with fake work.
- If selection is cancelled by the user, show `스캔을 멈췄어요` or return to start with no error banner.

### Progress and Cancellation

- Progress starts after selected items are available.
- Progress count updates as items are processed.
- Cancel stops remaining work and reaches the cancelled state.
- Already processed items may remain counted; skipped duplicates remain summarized.
- The bottom navigation remains visible unless a platform picker is open.

### Duplicate Handling

- Duplicates are skipped without per-item dialogs.
- When skipped count is greater than zero, show `이미 확인한 항목 {count}개는 건너뛰었어요`.
- If every selected item is a duplicate, show a neutral result state with the duplicate summary and `다시 선택`.

### Small Screen

- At 320x568 logical size, Scan start source choices are reachable without horizontal scrolling.
- On progress, `{processed}/{total} 처리 중` and `취소` are visible without text overlap.
- Long Korean labels may wrap; they must not overflow their parent.

## Accessibility Contract

- Minimum touch target: 44px; primary buttons should be 48px high.
- Body text: 16px or larger.
- Normal text contrast: 4.5:1 target or better.
- Progress and status are never color-only.
- Required semantics labels:
  - Photo source choice: `사진에서 쿠폰 찾기, 선택한 사진만 확인`
  - Downloads/file source choice: `다운로드와 파일에서 쿠폰 찾기, 선택한 파일만 확인`
  - Progress indicator: `선택한 항목 {total}개 중 {processed}개 확인`
  - Candidate placeholder: `쿠폰 후보 확인 준비 중`
  - Duplicate skip summary: `이미 확인한 항목 {count}개 건너뜀`
  - Cancel action: `스캔 취소, 남은 항목 확인 중지`
  - Empty result primary action: `다른 항목 다시 선택`
  - Disabled Phase 3 action: `후보 확인 화면은 다음 단계에서 연결됩니다`
- Screen readers should hear recovery actions on error states, not only the error title.
