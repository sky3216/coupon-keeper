<objective>
Replace the demo selected-source boundary with real platform-native photo, file, and folder pickers that stage original bytes locally and keep failures bounded and retryable.
</objective>

<user_story>
사용자로서 나는 사진 앱이나 Files에서 내가 직접 고른 이미지와 폴더만 쿠폰 후보로 확인하고 싶다.
</user_story>

<must_haves>
- Photos, files, and folder are explicit source types.
- Native adapters return opaque staged `file://` refs and stable non-path source tokens.
- Folder traversal stops at direct image children.
- Broad media/storage permissions are not added.
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-03.1-04: Source picker silently expands into broad-library or recursive scanning | high | Use system picker UI only, expose folder explicitly, and enumerate direct children without recursion. |
| T-03.1-05: Android implementation requests broad permissions or assumes Download root folder access | high | Use Photo Picker and SAF actions, keep manifest free of broad storage permissions, and treat folder as system-permitted selection. |
| T-03.1-06: iOS leaks security-scoped access or loses selected bytes before OCR | high | Coordinate reads, balance scoped access calls, and stage original bytes into app cache under opaque filenames. |
</threat_model>

Keep `AndroidManifest.xml` free of `READ_MEDIA_IMAGES`, `READ_EXTERNAL_STORAGE`, and `MANAGE_EXTERNAL_STORAGE`.

  - Staging streams bytes to cache, uses generated IDs, and computes SHA-256.
  - Retry handles can be processed without launching a new picker intent.
  - `AndroidManifest.xml` does not contain `READ_MEDIA_IMAGES`, `READ_EXTERNAL_STORAGE`, or `MANAGE_EXTERNAL_STORAGE`.
