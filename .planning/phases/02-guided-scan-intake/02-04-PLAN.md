<objective>
Fix the Phase 2 UAT gap where tapping a source in the real app jumps straight to empty state instead of showing progress. The default app path should exercise the same progress shell that injected widget tests already verify.
</objective>

<user_story>
As a first-time user testing the guided scan shell, I want tapping a source to show a finite progress state before any result state, so that I can trust the app is checking only the selected items and can cancel if needed.
</user_story>

<gap>
UAT Test 3 reported: "진행상태는 아직 나오지 않고 source 선택 화면 뒤에 `이번 선택에서는 쿠폰을 찾지 못했어요` empty 화면이 나온다."

Root cause: `ScanScreen` creates its default controller with `FakeScanSourcePicker.photos(const [])`, so production/default UI has zero selected items and immediately emits `GuidedScanStatus.empty`.
</gap>

<must_haves>
- The default `CouponKeeperApp` / `ScanScreen` path must show `선택한 항목을 확인하고 있어요` after tapping a source.
- The default path must show `{processed}/{total} 처리 중`, `후보 확인 준비 중`, and `취소` before completion/empty.
- This fix must not imply real OCR or real coupon discovery.
- No broad permissions, native picker packages, server upload, cloud sync, or fake coupon cards may be introduced.
- Tests must cover the default app path, not only an injected controller path.
</must_haves>

<truths>
- Phase 2 can use a fake/demo selected item adapter because native picker implementation is explicitly deferred.
- A demo selected item is not a fake coupon; it only drives the batch shell.
- Phase 3 will replace or extend this adapter with real OCR/candidate discovery.
</truths>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-02-11: Fix makes users think coupons were really found | high | Completion copy remains Phase 3 handoff only; tests reject found/protected value/save/edit text. |
| T-02-12: Fix adds broad native permission scope | high | Keep using Dart fake/demo adapter only; existing privacy guard must stay green. |
| T-02-13: Progress flashes too quickly to verify | medium | Default controller should use a small async delay so the progress state is observable in manual UAT and widget tests. |
</threat_model>
