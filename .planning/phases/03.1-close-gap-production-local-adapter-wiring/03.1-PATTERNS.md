# Phase 03.1 Pattern Map

## 목적

Phase 03.1은 Phase 1~3의 계약을 유지한 채 production adapter를 추가한다. fake adapter는 삭제하지 않고 테스트와 dependency injection에 남긴다.

## Existing Integration Points

### Production Composition

현재 `ScanScreen`이 demo picker, fake OCR, fake image store, in-memory repository를 직접 만든다. 새 `CouponKeeperDependencies`가 SQLite DB, real picker, MethodChannel OCR, local copy store, controller lifecycle을 소유하고 `CouponKeeperApp`이 async bootstrap 한다.

### Selected Source Boundary

`ScanItem.sourceToken`은 fingerprint용 안정 토큰이고 `platformSourceRef`는 일시적인 접근 reference다. 네이티브 picker는 opaque ID filename의 app-cache copy를 만들고 `file://` reference를 반환한다. OCR과 source preview는 이 transient reference를 소비한다.

### Durable Save Boundary

`CandidateDiscoveryController._save()`가 `ImageCopyStore.copyIntoAppStorage()`와 `PassRepository.save()`를 조율한다. 새 사본을 만든 뒤 repository write가 실패하면 새 사본만 정리한다. 이미 fingerprint로 재사용한 사본은 정리하지 않는다.

### Retry Boundary

`GuidedScanController`가 failed items를 보관하고 `retryFailed()`에서 picker를 다시 열지 않는다. `ScanScreen`은 `partial`과 `processingFailed` 상태에서 retry와 choose-again을 구분한다.

## Test Style

- SQLite unit test는 `sqflite_common_ffi`와 in-memory DB를 사용한다.
- 파일 사본 test는 temp directory와 byte equality를 사용한다.
- MethodChannel decode test는 Flutter mock method handler를 사용한다.
- native source assertion은 Android/iOS source에서 picker API, direct-child boundary, broad permission 부재를 검사한다.
- widget test는 fake adapter를 유지해 deterministic하게 retry와 save failure를 검증한다.

## Planning Guardrails

- `ScanScreen` 기본 경로에 demo/fake/in-memory 구현을 남기지 않는다.
- picker가 반환한 외부 원본 경로와 filename을 fingerprint 또는 내부 copy filename으로 노출하지 않는다.
- 폴더 처리에서 재귀 열거를 추가하지 않는다.
- picker 전체를 다시 여는 동작을 retry로 부르지 않는다.
- durable copy 또는 SQLite save 실패를 성공 화면으로 바꾸지 않는다.
- Wallet 목록과 상세 UI를 Phase 03.1에 끌어오지 않는다.
