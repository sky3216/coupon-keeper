## Problem Statement

사용자는 카카오톡 밖에서 받은 쿠폰, 교환권, 멤버십 바코드 이미지를 사진첩,
다운로드 폴더, 메시지, 이메일에 흩어진 상태로 둔다. 쿠폰이 있다는 사실은
매장 앞이나 결제 직전에 떠올리지만, 이미 만료되었거나 이미 사용한 이미지가
남아 있어 다시 헷갈리는 경우가 있다.

이 앱의 첫 문제 정의는 사진 정리가 아니다. 핵심 문제는 사용자가 보유한
현금성 이미지 자산을 잊어버리거나 만료시켜 손해를 보는 것이다.

## Demand Evidence

- 사용자는 사진 저장 공간 부족 때문에 Google One을 가족 요금제로 사용하고
  있다.
- 카카오톡 선물하기 쿠폰은 알림과 연장이 잘 되지만, 그 외 플랫폼에서
  구매하거나 선물받은 쿠폰은 놓쳐서 사라진 경험이 있다.
- 다운로드 폴더에는 사용자가 인지하지 못한 쿠폰 이미지가 10개 이내로 숨어
  있는 경우가 있다.
- 사진첩에서 "쿠폰"으로 검색해도 나오지 않는 쿠폰 이미지가 있다.
- 만료일을 직접 캘린더에 등록하는 사용자는 드물고, 쿠폰을 못 써서 날린
  경험은 흔하다.
- 3,900원 수준의 1회 구매라면 "나쁘지 않다"는 가격 반응이 있다.

## Status Quo

현재 사용자는 쿠폰을 체계적으로 관리하지 않는다.

1. 쿠폰을 받으면 다운로드 폴더나 사진첩에 저장한다.
2. 만료일 알림은 대부분 수동으로 등록하지 않는다.
3. 매장 앞에서 "이 매장 쿠폰이 있었던 것 같은데?"라고 떠올린다.
4. 사진첩이나 다운로드 폴더를 뒤져 쿠폰 이미지를 찾는다.
5. 결제에 성공하거나, 만료된 것을 그 자리에서 알게 된다.
6. 사용한 쿠폰 이미지는 귀찮아서 삭제하지 않는다.

이 흐름에서 사용자는 세 번 손해를 본다. 사용 전에 쿠폰 존재를 잊고, 사용
중에 찾느라 시간을 쓰고, 사용 후에 이미지를 정리하지 않아 다음에도 헷갈린다.

## Target User & Narrowest Wedge

초기 타깃은 기프티콘, 교환권, 멤버십 바코드, 예약/이벤트 쿠폰을 자주 받거나
구매하는 30대 직장인이다.

이 사용자는 카카오톡 외부 쿠폰을 자주 놓친다. 다운로드 폴더와 사진첩을
정리하지 않고, 쿠폰 만료일을 캘린더에 직접 넣는 습관도 없다. 다만 쿠폰 하나를
살릴 수 있다면 3,900원 정도의 1회 구매는 받아들일 가능성이 있다.

가장 작은 유료 제품은 "카카오톡 밖에 흩어진 쿠폰/교환권을 찾아 만료 전에
알려주는 로컬 쿠폰 지갑"이다.

## Constraints

- 서버를 사용하지 않는다.
- OpenAI API 같은 추가 AI 비용을 사용하지 않는다.
- 사진, 쿠폰 이미지, 위치 정보는 기기 밖으로 전송하지 않는다.
- iOS와 Android를 함께 지원한다.
- 첫 버전은 한국 시장에서 검증하되, 내부 구조는 다국어와 해외 확장을 막지
  않게 만든다.
- 파일명과 폴더명은 영어 kebab-case를 사용하고, 문서 내용은 한국어로 작성한다.

## Premises

1. 첫 제품은 사진 정리 앱이 아니라 "흩어진 쿠폰/교환권을 찾아 만료와 사용을
   도와주는 로컬 쿠폰 지갑"이다.
2. 무료 버전은 자동 탐지와 활성 쿠폰 5개 관리를 제공해 가치를 먼저 보여준다.
3. 유료 버전은 3,900원 1회 구매를 1차 가격으로 잡고, 무제한 쿠폰, 반복 알림,
   정리 후보 기능을 제공한다.
4. GPS 매장 근처 알림은 MVP 핵심이 아니라 "자주 가는 장소 등록 기반 Pro 확장
   기능"으로 둔다.
5. 해외판은 한국 쿠폰 앱이 아니라 "Apple Wallet/Google Wallet에 들어가지 못한
   이미지 패스를 찾아주는 local pass finder"로 포지셔닝한다.

## Approaches Considered

### Approach A: 쿠폰 지갑 MVP

한국 시장에서 먼저 쿠폰/교환권 자동 탐지, 만료 알림, 쿠폰 지갑, 사용 완료
처리를 검증한다. 무료는 활성 쿠폰 5개까지, Pro는 3,900원 1회 구매로 둔다.

장점:
- 가장 빨리 유료 구매 이유를 검증할 수 있다.
- "쿠폰 하나만 살려도 앱값 회수" 메시지가 강하다.
- 서버 없이 로컬 처리로 시작할 수 있다.
- 이후 멤버십, 바코드, 위치 리마인더로 확장하기 쉽다.

단점:
- 초기 시장은 한국형 앱처럼 보일 수 있다.
- OCR과 날짜 인식 품질이 구매 전환에 직접 영향을 준다.
- Wallet 보완재라는 포지셔닝을 명확히 해야 한다.

### Approach B: Local Pass Finder

처음부터 쿠폰, 멤버십, 바코드, 교환권, 티켓 이미지를 찾는 글로벌형 로컬 패스
탐색기로 간다.

장점:
- 해외 확장 메시지가 자연스럽다.
- Apple Wallet/Google Wallet에 못 들어간 이미지를 보완하는 포지션이 좋다.
- 쿠폰 외 사용처가 넓다.

단점:
- 첫 MVP 범위가 커진다.
- 국가별 날짜, 언어, 바코드, 문서 패턴 대응이 어렵다.
- 첫 유료 구매 명분이 쿠폰 만료 방지보다 흐려질 수 있다.

### Approach C: 위치 기반 쿠폰 리마인더

사용자가 자주 가는 장소를 등록하면 근처에 도착했을 때 관련 쿠폰을 알려준다.

장점:
- 사용 순간과 알림 타이밍이 좋다.
- Pro 기능으로 매력적이다.
- 매장 앞에서 바로 가치를 체감할 수 있다.

단점:
- 위치 권한 허들이 크다.
- 매장 데이터 없이 자동화가 어렵다.
- 개인정보 보호와 로컬 처리 메시지와 충돌할 수 있다.

## Recommended Approach

Approach A를 선택한다.

첫 목표는 글로벌 비전을 증명하는 것이 아니라, 사용자가 3,900원을 낼 만큼
"쿠폰 손실 방지"에 가치를 느끼는지 검증하는 것이다. Approach A는 가장 작고
명확하며, 서버 없는 로컬 앱이라는 제약에도 맞는다. 동시에 내부 데이터 모델을
패스, 바코드, 만료일, 장소, 언어팩 중심으로 잡으면 이후 Approach B와 C로 확장할
수 있다.

## MVP Scope

### 무료 버전

- 사진첩과 다운로드 폴더에서 쿠폰/교환권 후보 자동 탐지
- 활성 쿠폰 5개까지 등록
- 수동 등록 지원
- 만료 7일 전과 당일 알림
- 쿠폰 지갑에서 이미지와 바코드 바로 보기
- 사용 완료 처리
- 첫 스캔 리포트
- 예상 쿠폰 금액 표시
- 광고 없음

### Pro 1회 구매

- 활성 쿠폰 무제한
- 만료 7일 전, 3일 전, 1일 전, 당일 알림
- 사용자 지정 알림
- 사용 완료 후 원본 이미지 정리 후보 등록
- 브랜드/매장명 수동 태그 및 자동 추정
- 멤버십/바코드 이미지 등록

### MVP에서 제외

- 서버 동기화
- 계정 로그인
- 클라우드 백업
- 자동 매장 위치 데이터베이스
- 백그라운드 GPS 기반 자동 매장 탐지
- 첫 실행부터 전체 사진첩/다운로드 폴더를 조용히 훑는 자동 스캔
- 글로벌 다국어 OCR 전체 대응
- Apple Wallet/Google Wallet 패스 생성
- 무료 버전 광고 수익화

## Product Positioning

한국 첫 출시 문구:

> 카카오톡 밖에 흩어진 쿠폰과 교환권을 찾아 만료 전에 알려주는 로컬 쿠폰 지갑

글로벌 확장 문구:

> Find and protect the coupons, gift cards, and barcode passes that never made it into
> Apple Wallet or Google Wallet.

## Success Criteria

초기 검증 목표:

- 주변 사용자 5명에게 쿠폰 찾는 과정을 관찰한다.
- 각 사용자에게 다운로드 폴더/사진첩에 숨어 있는 쿠폰이 몇 개인지 확인한다.
- 최소 3명 이상이 "쿠폰을 못 써서 날린 경험"을 말한다.
- 최소 2명 이상이 3,900원 1회 구매에 긍정 반응을 보인다.
- 프로토타입에서 쿠폰 후보 탐지 후 60초 안에 첫 쿠폰 등록을 완료한다.

출시 후 지표:

- 첫 실행 권한 허용률
- 첫 스캔 완료율
- 첫 쿠폰 등록률
- 활성 쿠폰 5개 한도 도달률
- Pro 구매 전환율
- 사용 완료 처리율
- 만료 알림 클릭률

## Distribution Plan

첫 배포 채널은 iOS App Store와 Google Play다. 무료 앱으로 배포하고, Pro는
인앱 1회 구매로 제공한다. MVP에서는 무료 버전에도 광고를 넣지 않는다. 이 앱의
핵심 신뢰는 사진과 쿠폰 이미지를 기기 밖으로 내보내지 않는다는 점이므로, 광고
SDK로 인한 추적 동의와 개인정보 메시지 충돌을 피한다.

초기 마케팅은 "쿠폰 관리"보다 "못 쓴 쿠폰 찾기"로 잡는다. 앱스토어
스크린샷은 다음 장면을 보여줘야 한다.

1. 다운로드 폴더에서 숨어 있는 쿠폰 발견
2. 만료일 자동 추출
3. 지갑에 등록
4. 매장 앞에서 바로 꺼내 사용
5. 사용 완료 후 정리 후보 등록

## Open Questions

- 광고 수익화를 MVP 이후에 다시 검토할 경우, "로컬/개인정보 보호" 메시지와
  얼마나 충돌하는지 별도로 판단해야 한다.
- 무료 한도는 활성 쿠폰 5개가 적절한가, 3개 또는 10개가 더 나은가?
- Pro 가격은 3,900원으로 시작할지, 4,900원으로 A/B 테스트할지 결정해야 한다.

## CEO Review Scope Decisions

`plan-ceo-review`에서 제품 범위를 SELECTIVE EXPANSION 모드로 검토했다. MVP는
Approach A, 즉 손실 방지형 쿠폰 지갑으로 유지한다.

### Accepted into MVP

- 첫 스캔 리포트: 첫 실행에서 찾은 쿠폰 후보, 만료 임박 쿠폰, 이미 만료된
  것으로 보이는 쿠폰, 예상 보호 금액을 보여준다.
- 놓칠 뻔한 금액 표시: 금액은 "예상 쿠폰 금액"으로만 표시한다. OCR 신뢰도가
  낮거나 금액을 못 읽으면 숨기고, 사용자가 직접 수정할 수 있게 한다.
- 사용 완료 후 정리 후보: 사용 완료 처리 후 원본 이미지를 바로 삭제하지 않고
  정리 후보 목록에 넣는다.
- 무료 버전 광고 제거: MVP에서는 광고 SDK를 넣지 않고, 활성 쿠폰 5개 제한과
  Pro 기능 차이로 수익화를 검증한다.

### Deferred to Follow-Up

- Apple Wallet/Google Wallet 추가 기능: MVP가 아니라 후속 기능으로 둔다.
- 자주 가는 장소 기반 알림: 위치 권한과 심사 리스크가 있으므로 Pro 2단계
  기능으로 둔다.

### Not in Scope

- Wallet 대체 앱 포지셔닝
- 서버 동기화와 계정 기반 백업
- 자동 매장 위치 데이터베이스
- 백그라운드 GPS 기반 매장 자동 탐지

## The Assignment

구현 전에 주변 사용자 5명에게 휴대폰에서 쿠폰을 찾는 과정을 보여달라고 요청한다.
질문하지 말고 먼저 행동을 관찰한다. 다음 항목만 기록한다.

- 다운로드 폴더와 사진첩에 쿠폰/교환권이 몇 개 있는가
- 쿠폰을 찾는 데 몇 초가 걸리는가
- 만료된 쿠폰이 있는가
- 이미 사용했지만 남아 있는 쿠폰 이미지가 있는가
- 3,900원 1회 구매에 어떤 반응을 보이는가

이 관찰 결과가 나와야 MVP 범위와 무료/유료 경계를 더 정확히 정할 수 있다.

## What I Noticed

- "사진 정리"에서 시작했지만, 대화 중 실제 돈 되는 문제는 "쿠폰 손실 방지"로
  좁혀졌다.
- "무료는 활성 쿠폰 5개까지"라는 경계는 사용자가 가치를 먼저 느끼고 난 뒤
  구매를 고민하게 만들어 자연스럽다.
- GPS 알림 아이디어는 좋지만, MVP에 넣으면 위치 권한과 매장 데이터 문제 때문에
  출시 속도가 느려진다. Pro 확장 기능으로 두는 편이 낫다.
- 글로벌 확장은 가능하지만 첫 검증은 한국에서 해야 한다. 단, 데이터 모델은 처음부터
  쿠폰이 아니라 패스 중심으로 잡아야 한다.

## Engineering Review Architecture Decisions

`plan-eng-review`에서 MVP 구현 전에 아키텍처와 플랫폼 경계를 검토했다. 핵심
방향은 "서버 없는 로컬 앱" 원칙을 유지하되, OS 권한과 OCR 품질이 중요한 영역은
네이티브 구현으로 처리하는 것이다.

### Decisions Locked

- 권한 모델: MVP는 사용자가 사진과 폴더를 직접 선택하는 guided scan으로 시작한다.
  Pro 확장은 사용자가 명시적으로 허용한 경우에만 더 넓은 사진첩 또는 다운로드
  접근을 제공한다.
- 앱 프레임워크: Flutter를 공통 UI와 상태 관리 레이어로 사용하고, 사진 접근,
  파일 접근, OCR, 알림, 결제처럼 플랫폼 차이가 큰 기능은 Swift/Kotlin 네이티브
  채널로 감싼다.
- 로컬 저장소: 쿠폰 메타데이터는 SQLite에 저장하고, 쿠폰 표시용 이미지 사본은 앱
  내부 저장소에 보관한다. 원본 사진/파일은 참조만 유지한다.
- 데이터 모델: `coupon`이 아니라 `pass` 중심 모델로 시작한다. 쿠폰, 교환권,
  멤버십, 바코드 이미지를 같은 수명주기 안에서 다룰 수 있게 한다.
- OCR: MVP는 iOS Vision과 Android ML Kit Text Recognition v2를 사용한다. 공통
  레이어에서는 날짜, 금액, 브랜드, 바코드 후보를 규칙 기반으로 파싱한다.
- 후보 처리: OCR 결과는 자동 등록하지 않고 후보로 보여준다. 확신도가 낮은 값은
  숨기거나 사용자 확인을 요구한다.
- 알림: 쿠폰 저장/수정 시점에 로컬 알림을 예약하고, 앱 실행/복귀 시 누락되거나
  오래된 알림을 재조정한다.
- 결제: App Store와 Google Play 인앱결제를 사용하고, Pro 상태는 기기에 로컬
  캐시한다. MVP에서는 서버 영수증 검증을 도입하지 않는다.
- 정리 후보: 사용 완료 후 원본 이미지는 바로 삭제하지 않는다. 앱 안에 정리 후보로
  모으고, 실제 삭제는 사용자 확인 후 시스템 UI 또는 원본 앱으로 위임한다.

```text
  -> normalized OCR result
  -> coupon/pass candidate detector
  -> date/value/brand/barcode parser
  -> confirmation UI
  -> SQLite pass metadata
  -> app-internal image copy
  -> local notification scheduler
```

### NOT in Scope

- 서버 동기화, 계정, 클라우드 백업: 로컬-only 신뢰와 MVP 속도를 유지하기 위해
  제외한다.
- 서버 영수증 검증: 부정 구매 방지는 강화되지만 서버 운영과 계정 문제가 생기므로
  MVP 이후로 둔다.
- 첫 실행 전체 자동 스캔: 권한 허들과 심사 리스크가 커서 MVP에서는 guided scan을
  우선한다.
- 직접 원본 삭제: 오삭제 리스크가 크므로 정리 후보와 시스템 UI 위임까지만 제공한다.
- 자체 ML 분류 모델: MVP에서는 규칙 기반 파서로 시작하고, 사용자 수정 데이터를
  기반으로 고도화 여부를 판단한다.

  `lib/domain/` 또는 `test/fixtures/`처럼 앱 내부 구조로 먼저 둔다.

### Code Organization

Flutter 앱은 도메인 중심 레이어로 나눈다. 완전한 클린 아키텍처 템플릿을 강제하지는
않지만, 화면 코드가 플랫폼 권한, OCR SDK, 로컬 DB 세부사항을 직접 알지 않게 한다.

```text
lib/
  presentation/
  application/
  domain/
  data/
  platform/
```

- `presentation`: 화면, 위젯, 라우팅, 사용자 입력 처리
- `application`: 스캔 시작, 후보 승인, 사용 완료, 알림 재조정 같은 유스케이스
- `domain`: `Pass`, `ScanCandidate`, `ReminderPlan`, `Entitlement` 같은 순수 모델과 규칙
- `data`: SQLite repository, 이미지 사본 저장소, 로컬 entitlement 캐시
- `platform`: iOS/Android 사진 선택, 파일 접근, OCR, 알림, 인앱결제 어댑터

### Test Strategy

테스트는 단위 테스트, 위젯 테스트, 통합 테스트 3단으로 잡는다. 순수 로직은 빠른 단위
테스트로 넓게 덮고, 플랫폼 채널과 사용자 흐름은 mock 또는 테스트 더블을 둔 통합
테스트로 검증한다.

```text
CODE PATHS                                  USER FLOWS
[+] pass parser                              [+] First scan
  ├── [GAP] Korean date formats                ├── [GAP] [E2E] select photos/folder
  ├── [GAP] expired date                       ├── [GAP] OCR candidate appears
  ├── [GAP] no date found                      └── [GAP] approve candidate saves pass
  └── [GAP] value confidence

[+] reminder planner                         [+] Coupon use
  ├── [GAP] free D-7 + D-Day                   ├── [GAP] open pass detail
  ├── [GAP] Pro D-7/D-3/D-1/D-Day              ├── [GAP] mark used
  └── [GAP] expired/used cancels stale         └── [GAP] cleanup candidate appears

[+] entitlement gate                         [+] Pro purchase/restore
  ├── [GAP] active pass limit 5                ├── [GAP] purchase unlocks unlimited
  ├── [GAP] Pro cache present                  └── [GAP] restore failure keeps free usable
  └── [GAP] purchase unavailable
```

- 단위 테스트: 날짜/금액/브랜드 파서, 후보 점수, 알림 날짜 계산, Pro 권한 게이트
- 위젯 테스트: 첫 스캔 리포트, 후보 확인 화면, 쿠폰 상세, 사용 완료와 정리 후보 UI
- 통합 테스트: 사진/폴더 선택 mock, OCR 결과 mock, 후보 승인, SQLite 저장, 알림 예약,
  구매/복원 실패 시 무료 기능 유지

### Performance Strategy

첫 스캔은 한 번에 모든 이미지를 OCR하지 않는다. 사용자가 선택한 이미지와 폴더를 작은
배치로 처리하고, 진행률과 취소 버튼을 제공한다. 파일 fingerprint를 저장해 같은 이미지는
다시 OCR하지 않고, 후보 결과는 배치마다 점진 저장한다.

```text
scan request
  -> collect selected assets
  -> skip already-scanned fingerprints
  -> process small batch
  -> update progress
  -> persist candidates incrementally
  -> allow cancel/resume
```

### Failure Modes

- 사진 권한이 제한되거나 철회됨: 선택 가능한 사진/폴더를 다시 고르게 안내하고, 이미
  저장된 앱 내부 이미지 사본은 계속 보여준다.
- OCR이 날짜를 잘못 읽음: 확신도가 낮은 값은 자동 저장하지 않고 사용자 확인을 요구한다.
- 원본 이미지가 삭제됨: `image_copy_path`의 앱 내부 사본으로 쿠폰 지갑 표시는 유지한다.
- 알림 예약이 누락됨: 앱 실행/복귀 시 활성 쿠폰 기준으로 알림을 재조정한다.
- 구매 복원이 실패함: 무료 기능은 계속 사용할 수 있게 하고, 복원 재시도 진입점을 남긴다.
- 스캔 중 앱이 종료됨: 마지막 처리 fingerprint와 저장된 후보를 기준으로 재개할 수 있게 한다.

### Worktree Parallelization Strategy

구현은 3개 레인으로 나눌 수 있다.

| Lane | Modules touched | Depends on |
|------|-----------------|------------|
| A | `domain/`, `data/` | - |
| B | `platform/` | A의 인터페이스 |
| C | `presentation/`, `application/` | A의 모델, B의 테스트 더블 |

- Lane A: `Pass`, `ScanCandidate`, parser, reminder planner, SQLite schema를 먼저 만든다.
- Lane B: iOS/Android 사진/파일/OCR/알림/결제 어댑터를 플랫폼별로 구현한다.
- Lane C: 첫 스캔, 후보 확인, 지갑, 상세, Pro gate UI를 구현한다.
- 실행 순서: A를 먼저 고정한 뒤 B와 C를 병렬 진행할 수 있다. B/C는 `application/`
  인터페이스를 공유하므로 계약 변경 시 충돌 가능성이 있다.

## Design Review Decisions

`plan-design-review`에서 구현 전 UX 구조를 검토했다. Mockup 생성은 API key 기반
gstack designer 설정 전까지 뒤로 미루고, 먼저 텍스트 기반 디자인 기획을 문서화한다.

### Information Architecture

앱은 `Today`, `Wallet`, `Scan` 3개 하단 탭을 기본 구조로 한다. 첫 화면은 `Today`다.
사용자가 앱을 열었을 때 "지금 써야 하는 쿠폰"과 "새 쿠폰 찾기"를 동시에 발견하게
만든다.

```text
Bottom Nav
  Today
    - expiring soon
    - recently added
    - start scan CTA
    - first scan report summary
  Wallet
    - active
    - used
    - expired
    - cleanup candidates
  Scan
    - photos
    - downloads
    - manual add
```

- `Today`: 만료 임박 쿠폰, 최근 추가 쿠폰, 첫 스캔 리포트 요약, 스캔 시작 CTA를
  보여준다.
- `Wallet`: 활성, 사용 완료, 만료, 정리 후보를 필터로 전환한다.
- `Scan`: 사진 선택, 다운로드 폴더 선택, 수동 등록을 제공한다.
- 첫 실행 전에는 `Today` 상단에 "숨어 있는 쿠폰 찾기" CTA를 가장 크게 배치한다.
- 쿠폰이 하나 이상 등록된 뒤에는 `Today` 상단 우선순위를 만료 임박 쿠폰으로 바꾼다.

### Interaction States

핵심 화면은 로딩, 빈 상태, 오류, 성공, 부분 성공 상태를 모두 정의한다. 빈 상태는
막힌 화면이 아니라 다음 행동을 알려주는 화면이어야 한다.

| Feature | Loading | Empty | Error | Success | Partial |
|---------|---------|-------|-------|---------|---------|
| Today | 저장된 쿠폰과 알림 상태를 확인 중이라고 보여준다. | "아직 지갑이 비어 있어요"와 스캔 시작 CTA를 보여준다. | 최근 스캔/쿠폰 상태를 불러오지 못했음을 알리고 재시도 버튼을 둔다. | 만료 임박 쿠폰, 최근 추가 쿠폰, 스캔 CTA를 우선순위대로 보여준다. | 일부 쿠폰이 만료되었거나 원본이 사라졌음을 작은 상태 배지로 보여준다. |
| Scan | 배치 단위 진행률, 남은 항목 수, 취소 버튼을 보여준다. | "이번 선택에서는 쿠폰을 찾지 못했어요"와 수동 등록 CTA를 보여준다. | 권한 거부, 파일 접근 실패, OCR 실패를 구분해 복구 행동을 제시한다. | 후보 목록과 예상 만료일/금액/브랜드를 보여준다. | 확신도가 낮은 후보는 "확인 필요"로 분리하고 자동 저장하지 않는다. |
| Wallet | 쿠폰 목록을 불러오는 skeleton을 보여준다. | "사용할 수 있는 쿠폰이 없어요"와 Scan 탭 CTA를 보여준다. | 목록을 불러오지 못했음을 알리고 재시도 버튼을 둔다. | 활성, 사용 완료, 만료, 정리 후보 필터로 그룹화해 보여준다. | 활성 쿠폰은 없지만 만료/사용 완료 항목이 있으면 해당 필터로 안내한다. |
| Pass Detail | 이미지와 바코드를 불러오는 skeleton을 보여준다. | 이미지 사본이 없으면 원본 다시 선택 또는 수동 정보 보기로 안내한다. | 이미지 표시 실패, 바코드 인식 실패, 알림 예약 실패를 구분한다. | 쿠폰 이미지, 바코드, 만료일, 사용 완료 버튼을 즉시 사용할 수 있게 한다. | 원본 참조가 사라져도 앱 내부 사본으로 사용은 가능하다고 알려준다. |
| Pro Gate | 스토어 상품과 기존 구매 상태를 확인 중이라고 보여준다. | 무료 기능은 계속 사용 가능하다는 문구와 현재 한도를 보여준다. | 구매 실패, 복원 실패, 스토어 지연을 구분하고 재시도와 나중에 하기 버튼을 둔다. | Pro 활성화와 열린 기능을 명확히 보여준다. | 스토어 응답이 늦어도 무료 기능으로 돌아갈 수 있게 한다. |
| Cleanup | 정리 후보의 원본 참조 상태를 확인 중이라고 보여준다. | "정리할 이미지가 없어요"와 사용 완료 쿠폰 설명을 보여준다. | 원본 앱/시스템 UI를 열 수 없으면 직접 찾기 안내를 제공한다. | 정리 후보 목록과 원본 열기/삭제 위임 액션을 보여준다. | 원본이 사라진 후보는 목록에서 상태 배지로 구분한다. |

### User Journey and Emotional Arc

첫 스캔은 후보 목록으로 바로 보내지 않고 발견 리포트를 먼저 보여준다. 사용자가
"앱이 내 쿠폰을 찾아줬다"는 감각을 받은 뒤 후보를 확인하게 만든다.

```text
STEP | USER DOES              | USER FEELS       | UI SUPPORT
-----|------------------------|------------------|------------------------------
1    | opens app first time   | skeptical        | local/private promise + scan CTA
2    | selects photos/folder  | cautious         | system picker, selected-only copy
3    | waits during scan      | impatient        | progress, cancel, live candidate count
4    | sees scan report       | surprised/relief | found count, expiring soon, value estimate
5    | confirms candidates    | in control       | edit expiry/value, reject false positives
6    | gets reminder later    | protected        | clear expiry notification
7    | marks used             | tidy             | cleanup candidate, no auto-delete
```

첫 스캔 리포트의 우선순위:

1. 찾은 쿠폰/교환권 후보 개수
2. 만료 임박 후보 개수
3. 이미 만료되었을 가능성이 있는 후보 개수
4. 예상 보호 금액
5. "후보 확인하기" CTA

예상 금액은 항상 추정치로 표현한다. 금액을 읽지 못했거나 확신도가 낮으면 숫자를
보여주지 않는다.

### Visual Direction

시각 방향은 "조용한 지갑 + 큰 쿠폰 프리뷰"로 잡는다. Today와 Wallet은 차분한 리스트
중심으로 빠르게 훑게 만들고, Pass Detail에서만 쿠폰 이미지와 바코드를 크게 보여준다.

```text
Today
  - calm list
  - one prominent expiring item
  - one scan CTA

Wallet
  - compact grouped list
  - status chips
  - thumbnail only

Pass Detail
  - large coupon image
  - full-width barcode area
  - expiry/status/action fixed near thumb
```

금지할 패턴:

- 모든 쿠폰을 큰 카드 그리드로 보여주는 대시보드형 화면
- 장식용 아이콘 카드 묶음
- 보라/파랑 그라데이션 중심의 일반적인 SaaS 느낌
- 사용 설명 문구가 화면 대부분을 차지하는 온보딩
- 만료 정보보다 이미지 장식이 더 먼저 보이는 목록

### Mini Design System

MVP에서는 별도 대형 디자인 시스템보다 구현자가 바로 적용할 수 있는 미니 디자인
시스템을 먼저 사용한다. 앱 스캐폴드가 만들어지고 mockup이 확정되면 `DESIGN.md`로
분리한다.

```text
Color roles
  background: warm off-white or neutral light
  surface: white
  text-primary: near-black
  text-secondary: neutral gray
  accent: coupon-safe green or clear blue
  danger: expiry red
  warning: expiring amber

Type
  title: 22-24
  section: 17-18
  body: 16
  meta: 13-14

Components
  primary button
  secondary text button
  status chip
  pass row
  scan progress row
  barcode panel
  bottom nav
```

컴포넌트 원칙:

- `pass row`: 브랜드명, 만료일, 상태 칩, 작은 썸네일만 보여준다.
- `status chip`: `D-7`, `D-3`, `오늘 만료`, `사용 완료`, `확인 필요`, `원본 없음`을
  짧고 명확하게 표현한다.
- `barcode panel`: 상세 화면에서만 크게 보여주며 밝기와 대비를 충분히 확보한다.
- `primary button`: 화면당 하나만 둔다. 첫 스캔 전에는 "숨어 있는 쿠폰 찾기", 후보
  확인 단계에서는 "선택한 쿠폰 저장"처럼 구체적 행동을 적는다.
- `bottom nav`: `Today`, `Wallet`, `Scan` 3개만 사용한다.

### Responsive and Accessibility

모바일 앱의 핵심 상황은 한 손으로 빠르게 쿠폰을 찾고 매장 앞에서 바코드를 보여주는
것이다. 접근성 기준은 출시 직전 QA가 아니라 MVP 구현 기준에 포함한다.

```text
Mobile layout
  - one-handed primary actions near bottom
  - coupon detail action bar fixed at bottom
  - pass row supports 2-line brand/title
  - barcode area has tap-to-expand

Accessibility
  - 44px min touch targets
  - body text 16px+
  - contrast 4.5:1+
  - state never color-only
  - screen reader labels for barcode, expiry, status, actions
```

구체 기준:

- 주요 CTA와 사용 완료 버튼은 한 손 조작이 쉬운 하단 영역에 둔다.
- 쿠폰 상세 화면은 이미지/바코드를 크게 보여주되, 하단 고정 액션 바가 바코드를 가리지
  않게 한다.
- 바코드 영역은 탭하면 전체 화면 또는 확대 모드로 전환할 수 있어야 한다.
- 브랜드명과 쿠폰명은 2줄까지 허용하고, 더 길면 말줄임 처리한다.
- 만료 상태는 색뿐 아니라 텍스트와 아이콘/배지 문구로 표현한다.
- 스크린리더에는 "스타벅스 아메리카노 쿠폰, 오늘 만료, 바코드 표시됨"처럼 상태를
  합쳐 읽을 수 있는 라벨을 제공한다.
- 320px 폭에서도 버튼 텍스트가 잘리지 않아야 한다.

### Pro Conversion UX

Pro 전환 화면은 맥락형으로만 보여준다. 사용자가 아직 가치를 경험하기 전에는 결제를
요구하지 않는다.

```text
Show Pro when:
  - user tries to save 6th active pass
  - user taps custom reminders
  - user taps unlimited scan/save affordance
  - user opens cleanup candidates after marking used

Do not show Pro when:
  - first launch
  - before first scan
  - before user confirms at least one candidate
```

Pro 화면의 메시지는 기능 나열보다 "쿠폰 하나만 살려도 앱값 회수"에 맞춘다. 단, 과장된
절약 금액은 쓰지 않고 사용자가 실제로 찾은 후보와 활성 쿠폰 한도 상황을 기준으로
보여준다.
