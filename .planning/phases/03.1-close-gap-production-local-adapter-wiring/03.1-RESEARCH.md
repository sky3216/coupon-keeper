# Phase 03.1 Research: Production Local Adapter Wiring

## Research Goal

Phase 03.1은 Phase 1~3에서 이미 만든 계약과 UI를 버리지 않고, 기본 실행 경로의 데모 어댑터를 실제 로컬 어댑터로 교체한다.

1. 사용자가 명시적으로 고른 사진, 이미지 파일, 폴더 직접 자식 이미지만 가져온다.
2. 선택한 이미지는 원본 바이트를 유지한 채 앱 캐시에 임시 스테이징하고 기존 온디바이스 OCR에 전달한다.
3. 확인된 pass, fingerprint, 앱 내부 이미지 사본 레지스트리를 SQLite와 앱 내부 디렉터리에 보존한다.
4. 개별 항목 실패가 성공 항목을 버리지 않게 하고, 실패 항목만 다시 시도한다.

## Official Platform Findings

### Android: 사진과 문서 선택

Android 공식 Photo Picker 문서는 `PickMultipleVisualMedia`로 여러 사진을 선택할 수 있고, Photo Picker가 없는 기기에서는 AndroidX Activity가 `ACTION_OPEN_DOCUMENT`로 대체한다고 설명한다. 사진 경로는 broad media permission 없이 시스템 picker를 사용한다.

Storage Access Framework 문서는 이미지 파일 선택에 `ACTION_OPEN_DOCUMENT`, 폴더 선택에 `ACTION_OPEN_DOCUMENT_TREE`를 사용하도록 안내한다. 폴더 권한은 선택한 디렉터리 트리까지 넓지만 Coupon Keeper는 D-04에 따라 직접 자식 이미지 파일만 열거한다.

Android 11(API 30) 이상에서는 `ACTION_OPEN_DOCUMENT_TREE`로 내부 저장소 루트, 신뢰 가능한 SD 카드 루트, `Download` 디렉터리 자체를 선택할 수 없다. 따라서 `다운로드/파일에서 찾기`는 이미지 파일 다중 선택을 기본 경로로 두고, `폴더에서 찾기`는 시스템이 허용하는 폴더를 명시적으로 고르는 별도 경로로 제공한다.

### iOS: 사진과 Files 선택

Apple 공식 `PHPickerConfiguration.selectionLimit` 문서는 `0`을 설정하면 시스템이 지원하는 최대 개수까지 선택할 수 있다고 설명한다. 사진 경로는 `PHPickerViewController`와 이미지 필터를 사용한다.

Apple 공식 `UIDocumentPickerViewController` 문서는 외부 sandbox 문서를 열 수 있고 `allowsMultipleSelection`으로 여러 문서를 선택할 수 있다고 설명한다. Apple의 directory access 문서는 iOS 13부터 document picker로 폴더를 고를 수 있고, 반환된 security-scoped URL을 사용할 때 `startAccessingSecurityScopedResource()`, file coordinator, `stopAccessingSecurityScopedResource()` 순서를 지키도록 안내한다.

### Flutter: SQLite와 앱 내부 파일

Flutter 공식 SQLite cookbook은 `sqflite`와 `path`를 사용해 DB 경로를 만들고 `openDatabase()`로 테이블을 생성하는 기본 패턴을 제공한다. `sqflite_common_ffi` 문서는 에뮬레이터 없이도 unit test에서 SQLite 구현을 사용할 수 있다고 안내한다.

Flutter 파일 저장 cookbook과 `path_provider` API는 앱 전용 support 디렉터리를 구할 수 있다고 설명한다. Coupon Keeper의 durable 이미지 사본은 사용자에게 노출되지 않는 앱 내부 파일이므로 `getApplicationSupportDirectory()` 아래에 둔다.

## Recommended Architecture

아래 설계는 공식 picker와 sandbox 제약, 현재 코드의 `ScanSourcePicker`, `GuidedScanController`, `ImageCopyStore`, `PassRepository` 경계를 함께 고려한 구현 추론이다.

```text
ScanScreen
  -> GuidedScanController.start(sourceType)
  -> MethodChannelScanSourcePicker.pick(sourceType)
  -> native system picker
  -> app-cache staged original-byte images + stable SHA-256 source token
  -> GuidedScanController.process selected items
  -> MethodChannelOcrTextRecognizer
  -> CandidateDiscoveryController review-only candidates
  -> user confirms save
  -> LocalImageCopyStore copy/reuse by fingerprint
  -> SqlitePassRepository.save(Pass)
```

### Selected Source Staging

선택한 외부 리소스를 그대로 장기간 붙잡지 않는다. 네이티브 picker adapter가 앱 캐시 아래 opaque ID 파일명으로 원본 바이트를 복사하고, Dart에는 `file://` 스테이징 URL과 안정적인 `sha256:<digest>` source token을 반환한다.

- 원본 파일명과 원본 경로는 fingerprint나 스테이징 파일명에 넣지 않는다.
- 사진, 이미지 파일, 폴더 직접 자식 이미지를 같은 `ScanItem` 형태로 정규화한다.
- 개별 스테이징 실패는 picker 전체 실패로 바꾸지 않는다. adapter가 retryable failure handle을 유지하고 성공 항목은 계속 전달한다.
- reset 또는 batch 종료 시 남은 임시 스테이징 파일과 native handle을 해제한다.

### SQLite Schema

공유 `CouponKeeperDatabase`가 versioned schema를 연다.

| Table | Purpose |
|-------|---------|
| `passes` | `Pass` 전체 필드, source metadata, OCR text, confidence, timestamps 보존 |
| `scan_fingerprints` | 앱 재실행 후에도 이미 처리한 source fingerprint skip |
| `image_copies` | source fingerprint별 durable app-internal copy path 재사용 |

`SqlitePassRepository`는 기존 `PassRepository` 계약을 구현한다. `SqliteScanFingerprintCache`는 기존 in-memory test double과 같은 batch duplicate semantics를 유지한다. `LocalImageCopyStore`는 application support 디렉터리의 `coupon-images/` 아래 opaque generated ID 파일명으로 원본 바이트를 복사한다.

`ImageCopyStore.copyIntoAppStorage()`는 path 문자열만 반환하지 않고 `ImageCopyResult(path, created)`를 반환한다. 저장소 write가 실패했을 때 새로 만든 사본만 정리하고 이미 재사용 중인 사본은 삭제하지 않기 위해서다.

### Partial Failure and Retry

`GuidedScanController`는 실패한 `ScanItem`과 picker의 retryable source failure handle을 보관한다.

- 첫 처리에서 성공한 후보는 `CandidateDiscoveryController`에 남는다.
- `retryFailed()`는 시스템 picker를 다시 열지 않고 실패 항목만 처리한다.
- 재시도 후에도 실패가 남으면 남은 개수, 다시 시도, 다시 선택을 함께 보여준다.
- 성공 후보가 하나라도 있으면 실패 항목을 나중에 다시 선택하더라도 기존 성공 후보를 검토할 수 있다.

## Security and Privacy Notes

- OCR은 기존 iOS Vision, Android ML Kit 채널만 사용한다.
- `READ_MEDIA_IMAGES`, 광범위 저장소 권한, 네트워크 client, cloud SDK를 추가하지 않는다.
- source token, cache filename, durable copy filename에 원본 파일명이나 원본 경로를 넣지 않는다.
- OCR candidate는 review-only이며 사용자가 저장을 누르기 전에는 `passes` 테이블에 기록하지 않는다.
- durable copy 실패 또는 DB save 실패를 성공으로 표시하지 않는다.

## Validation Architecture

### Unit

- SQLite pass repository restart persistence와 status query parity
- SQLite fingerprint cache restart persistence와 in-batch duplicate skip
- durable image copy original-byte equality, generated filename, fingerprint reuse
- 새 사본 생성 후 repository save 실패 시 rollback, 재사용 사본은 보존
- failed-item-only retry와 성공 후보 보존

### Flutter Platform Contract

- `MethodChannelScanSourcePicker`가 selected, cancelled, access-denied, file-unavailable, retryable failure map을 정규화
- photo, downloads, folder sourceType을 native method로 전달
- production composition이 demo picker, fake OCR, fake copy store, in-memory repository를 기본 경로에 사용하지 않음

### Native Contract

- Android: `PickMultipleVisualMedia`, `ACTION_OPEN_DOCUMENT`, `ACTION_OPEN_DOCUMENT_TREE`, 직접 자식 열거, broad storage permission 부재
- iOS: `PHPickerViewController`, `selectionLimit = 0`, `UIDocumentPickerViewController`, `allowsMultipleSelection`, `.folder`, security-scoped access 해제
- Android debug APK build와 emulator smoke
- iOS smoke는 현재 Xcode/CoreSimulator 환경 blocker 복구 후 별도 실행
