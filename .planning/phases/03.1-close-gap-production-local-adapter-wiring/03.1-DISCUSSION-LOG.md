## Partial-Failure Recovery

### Mixed Batch Failure

| Option | Description | Selected |
|--------|-------------|----------|
| Continue remaining items | Preserve useful results and summarize failures later. | ✓ |
| Stop the full batch immediately | Surface failure early but discard pending useful work. | |
| Ask after every failure | Provide fine control but interrupt batch processing repeatedly. | |

**User's choice:** Continue remaining items
**Notes:** One failed file must not discard successful candidates.

### Completion Report Detail

| Option | Description | Selected |
|--------|-------------|----------|
| Failure count plus retry action | Calm report with a clear recovery path. | ✓ |
| Show failure list immediately | More detail but a noisier first report. | |
| Failure count only | Simple report with weak recovery guidance. | |

**User's choice:** Failure count plus retry action
**Notes:** Technical details should stay out of the normal user-facing report.

### Retry Scope

| Option | Description | Selected |
|--------|-------------|----------|
| Retry failed items only | Avoid repeating successful work. | ✓ |
| Retry full original selection | Simpler but wastes time and risks duplicate processing. | |
| Reopen the system picker | Make the user choose the range again. | |

**User's choice:** Retry failed items only
**Notes:** Preserve already successful work.

### Repeated Failure

| Option | Description | Selected |
|--------|-------------|----------|
| Show remaining count and choose-again path | Allow recovery without an endless retry loop. | ✓ |
| Keep offering retry only | Simple but can trap the user. | |
| Show technical error detail | Helpful for diagnosis but too technical for normal UX. | |

**User's choice:** Show remaining count and choose-again path
**Notes:** The user may retry again, but must always have a clear way out.
