<objective>
Guided scan intake의 domain, data, platform contract와 controller를 만든다. UI나 native picker보다 먼저, 선택된 항목만 처리하고 중복을 건너뛰며 취소 가능한 batch 상태를 deterministic하게 검증한다.
</objective>

<user_story>
사용자로서 나는 내가 선택한 사진이나 다운로드 파일만 Coupon Keeper가 확인하기를 원한다. 이미 확인한 항목은 다시 처리하지 않고, 중간에 멈추면 아직 처리하지 않은 항목은 다음에 다시 선택할 수 있어야 한다.
</user_story>

<must_haves>
- SCAN-02: 전체 사진첩이나 전체 폴더를 조용히 훑지 않고 user-selected item만 받는다.
- SCAN-03: processed/total, candidate placeholder, duplicate skip count, cancel state를 표현한다.
- SCAN-04: fingerprint cache로 이미 확인한 항목을 skip한다.
- D-03: photos source와 downloads/files source를 분리한다.
- D-05: progress는 processed/total, candidate placeholder, duplicate skip count, cancel을 포함한다.
- D-06: 후보 수는 실제 발견처럼 보이면 안 된다.
- D-07: cancel은 아직 처리하지 않은 항목을 중단하고 recoverable state로 돌아간다.
- D-09: fingerprint cache는 app/data contract로 두고 native file access 없이 test한다.
- D-10: duplicate skip은 조용히 처리하되 summary count로 표시 가능해야 한다.
- D-11: fingerprint record는 source identity/content signature에 scoped된다.
- D-13: user-cancelled, access-denied, file-unavailable, processing-failed를 구분한다.
- D-15: platform adapter는 media/file selection과 metadata만 담당한다.
</must_haves>

<truths>
- Phase 2는 OCR, candidate extraction, discovery report, pass 저장을 하지 않는다.
- Controller는 fake picker로 모든 핵심 branch를 test할 수 있어야 한다.
- 취소된 항목과 실패한 항목은 fingerprint cache에 mark하지 않는다.
- Domain/data/application 파일은 Flutter UI import 없이 순수하게 유지한다.
</truths>

<context_decision_coverage>
- D-03: `ScanSourceType.photos`와 `ScanSourceType.downloads` 또는 `files`를 분리한다.
- D-05: `ScanProgress`가 progress count, duplicate skip count, cancellable state를 가진다.
- D-06: `candidateCountKnown` 또는 equivalent flag로 Phase 3 전 placeholder를 명확히 한다.
- D-07: controller cancel branch는 남은 selected items를 처리하지 않는다.
- D-09: `ScanFingerprintCache` abstract contract와 in-memory 구현을 추가한다.
- D-10: duplicate summary count를 controller result에 포함한다.
- D-11: fingerprint tests는 repeat selections are skipped and distinct source signatures are not conflated.
- D-13: `ScanFailure` variant를 분리한다.
- D-15: `ScanSourcePicker` interface와 fake implementation을 추가한다.
</context_decision_coverage>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-02-01: 앱이 raw absolute file path를 fingerprint로 저장함 | high | Fingerprint input은 adapter-provided stable token으로 제한하고 tests에서 raw path 저장이 없는지 확인한다. |
| T-02-02: 취소된 item을 scanned로 mark함 | high | Controller test에서 cancel 이후 unprocessed item이 cache에 없는지 검증한다. |
| T-02-03: access denied, file missing, processing failure가 한 에러로 뭉개짐 | medium | Failure enum/sealed type과 branch별 unit test를 둔다. |
| T-02-04: 후보 수 placeholder가 fake 발견 수로 구현됨 | medium | Candidate count는 unknown/placeholder 상태로만 모델링한다. |
</threat_model>
