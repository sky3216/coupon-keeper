<objective>
Polish the Phase 1 shell into a reusable, accessible UI foundation that encodes the approved UI-SPEC, status chip language, pass row surface, and final verification checks.
</objective>

<user_story>
As a Coupon Keeper user, I want the empty app shell and pass status language to feel consistent and readable on a small phone, so that I trust the app before connecting real scan and wallet data.
</user_story>

<must_haves>
- SHELL-01/SHELL-02: App shell still launches and navigates after UI extraction.
- SHELL-03: Empty states explain next action with exact copy.
- SHELL-04: Primary actions and chips fit on 320px-wide screens.
- PASS-01: UI has reusable surfaces for pass fields without requiring fake saved passes.
- PASS-02: UI has a source-missing status chip and future pass row semantic label pattern.
- PASS-03: UI exposes active/expiry/used/cleanup/needs-review/source-missing state language.
- D-13: Phase 1 UI is a usable app shell, not a wireframe.
- D-14: Visual tone is quiet wallet utility.
- D-15: Core state chips are prepared.
- D-16: Accessibility criteria are applied from the start.
- UI-SPEC: Exact color, type, spacing, copy, component, and accessibility contracts.
</must_haves>

<truths>
- D-13: Phase 1 UI is a usable app shell, not a wireframe.
- D-14: Visual tone is quiet wallet utility.

</truths>

<context_decision_coverage>
- D-13: Phase 1 UI는 와이어프레임이 아니라 실사용 가능한 앱 셸이어야 한다. Today/Wallet/Scan 탭, 빈 상태, 주요 CTA, 기본 상태 칩/리스트 표면을 후속 phase가 재사용할 수 있게 만든다.
- D-14: 시각 톤은 조용한 지갑 유틸리티다. 매장 앞에서 빠르게 읽고 쓸 수 있는 차분하고 밀도 있는 모바일 도구처럼 느껴져야 한다.
- D-15: 상태 표현은 핵심 상태 칩 전체를 준비한다. `D-7`, `오늘 만료`, `만료됨`, `사용 완료`, `확인 필요`, `원본 없음` 같은 칩/라벨 패턴을 Phase 1에서 잡는다.
- D-16: 접근성은 처음부터 기준 통과를 목표로 한다. 44px 이상 터치 타깃, 16px 이상 본문, 4.5:1 이상 대비, 색 외 상태 표현, 주요 action/status screen reader label을 적용한다.
</context_decision_coverage>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| UI polish introduces fake coupon data | medium | Build reusable `PassRow` surface and tests without rendering fake rows in empty Wallet by default. |
| Status meaning relies on color only | medium | Every chip includes visible text and a semantic label. |
| Small-screen layout regresses after component extraction | medium | Keep 320x568 widget test as a required verification. |
</threat_model>
