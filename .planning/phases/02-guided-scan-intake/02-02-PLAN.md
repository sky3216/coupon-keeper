<objective>
Scan 화면을 Phase 2 guided intake UI로 교체한다. 사용자는 source를 고르고, 진행 상태를 보고, 취소하거나 empty/error/completion shell을 이해할 수 있어야 한다.
</objective>

<user_story>
첫 사용자로서 나는 Scan 화면에서 사진 또는 다운로드/파일 중 어디를 확인할지 고르고, 앱이 선택한 항목만 처리 중임을 보며, 필요하면 즉시 멈출 수 있어야 한다.
</user_story>

<must_haves>
- SCAN-01: Today CTA와 Scan tab으로 guided scan 시작점에 도달한다.
- SCAN-02: source choices는 `사진에서 찾기`, `다운로드/파일에서 찾기`를 제공한다.
- SCAN-03: progress는 `{processed}/{total} 처리 중`, `후보 확인 준비 중`, duplicate skip line, `취소`를 포함한다.
- D-01: Scan tab이 guided start surface다.
- D-02: Today/Wallet은 picker를 직접 열지 않고 Scan tab으로 이동한다.
- D-04: copy는 selected items only, on-device, no silent library scan 신뢰 약속을 유지한다.
- D-05: progress view는 processed/total, candidate placeholder, duplicate skipped, cancel을 표시한다.
- D-08: progress/result UI는 fail, skip, unprocessed 상태를 전체 실패처럼 보이지 않게 표현한다.
- D-10: duplicate skip summary는 `이미 확인한 항목 {count}개는 건너뛰었어요`를 사용한다.
- D-12: empty state는 `이번 선택에서는 쿠폰을 찾지 못했어요`를 사용한다.
- D-13: access denied, file unavailable, processing failed copy를 분리한다.
- UI-SPEC: 모든 user-facing copy는 `02-UI-SPEC.md`와 일치해야 한다.
</must_haves>

<truths>
- UI는 discovery report를 보여주지 않는다.
- UI는 fake coupon card나 fake count를 만들지 않는다.
- Today/Wallet CTA navigation은 Phase 1의 `AppShell` pattern을 유지한다.
- 화면은 320x568 logical size에서 primary actions가 보이고 tappable해야 한다.
</truths>

<context_decision_coverage>
- D-01: Scan screen idle state를 guided start로 만든다.
- D-02: Today/Wallet CTA test를 유지해 Scan tab 이동만 검증한다.
- D-03: 사진과 다운로드/파일 choice를 별도 button/list row로 제공한다.
- D-04: trust line과 body copy로 selected-only/on-device/no silent scan을 검증한다.
- D-05: progress UI에 count, placeholder, duplicate skip, cancel을 둔다.
- D-06: `후보 확인 준비 중` copy만 사용한다.
- D-08: partial success branches are supported by distinct summary/error copy.
- D-10: duplicate summary copy를 exact text로 검증한다.
- D-12: empty result copy를 exact text로 검증한다.
- D-13: error state variants를 exact text로 검증한다.
</context_decision_coverage>
